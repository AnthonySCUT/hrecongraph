# 第 17 阶段：冻结配置与端到端 QA

## 核心改动

冻结去重全文、词形作用域 Top-1／`w=1`、条件 Top-2／`w=1` 三组配置，使用相同 GLM-5.1 与 Prompt 生成答案。研究指标为 QA Accuracy、Stale Misuse、实际输入／输出 Token 和回答延迟。

三组共享命中 Session 与写入状态；来源日期与提问日期参与回答。更新题在生成答案前标定旧值、有效新值与原文位置，评分判断最终答案是否误用旧值。三份匿名答案通过一次调用完成语义评分。

## 代码变更

- 现有 `evaluate_longmemeval_read.py` 增加 `--qa-dir` 入口，保存冻结清单、上下文、调用与逐题评分，支持断点复用。
- 回答、更新标注、评分分别统计实际 usage；正确率报告有效题数和 Wilson 区间，配置差异报告配对结果。
- 现有测试增加四项用例。完整代码对照见[逐文件报告](../details/17-冻结配置与端到端QA逐文件交付.md)，差异见[批次补丁](../patches/17-冻结配置与端到端QA.patch)。

## 验证结果

指定回归 **165 passed**，Ruff 与格式检查通过。500 题的 1,500 份上下文已准备；Top-1／Top-2 逐题复现第 16 批上下文估算成本。

六题试跑完成全部 18 份回答和 6 次评分，三组正确数为 5/6、5/6、6/6。全量执行保存 578 份回答和 78 份更新标注；55 个更新题具有已核对的旧／新原文引用。

全量期间指定 Key 返回 HTTP 401「无效的令牌」，有效评分题数为 0。全量结果与日志保留为续跑记录；当前进度见[执行复核](../results/17-QA执行复核.json)，[逐题结果](../results/17-端到端QA逐题结果.json)、[六题试跑](../results/17-端到端QA六题试跑.json)与[复现说明](../reproduction.md)提供数据和调用口径。
