# 第七批：忠实性与读取成本对照

## 核心改动

以 16 个机制样本开展固定上下文配对：每题共用同一问题、图关系、来源与语义证据，仅切换 `full_source` 和 `evidence_bundle`。样本覆盖事实、约束、路径、因果四维，以及同段、跨段、缺少锚点和关系改写情形。

## 代码变更

- `read_context_cases.json`：记录问题、来源、必要证据与答案探针。
- `evaluate_read_context.py`：逐题运行两种读取模式并汇总必要证据保留、完整样本、答案探针、字符数和渲染时间。
- `test_h_recongraph_retrieval.py`：验证对照统计与增加跨段来源锚点后的变化。

[完整逐文件报告](../details/07-忠实性与读取成本对照逐文件交付.md)，含代码对比、示例与实验分析。

## 验证结果

| 指标 | `full_source` | `evidence_bundle` |
|---|---:|---:|
| 总字符数 | 4,557 | 2,896 |
| 必要证据保留率 | 100.00% | 88.57% |
| 完整样本 | 16/16 | 12/16 |

证据束文本减少 **36.45%**。遗漏集中在缺少来源锚点的事实、约束、路径和因果段落；该诊断推动第八批补齐写入端证据绑定。

- 指定三文件回归：**113 passed**。
- Ruff check、format check 与 `git diff --check` 通过。
