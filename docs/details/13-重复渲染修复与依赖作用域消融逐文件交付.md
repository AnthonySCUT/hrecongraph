# 第十三批：重复渲染修复与依赖作用域消融

## 核心改动

本批将三个因素分别对照：**图事实重复渲染、窗口扩展对象、自动依赖的词面相关性筛选**。Top-1 继续作为默认锚点，全文继续作为默认来源模式；图事实来源复用接入默认渲染，窗口与依赖筛选通过显式参数开展消融。

1. **复用已选来源中的事实正文。** 当 `edge.fact` 已逐字出现在最终选中的来源文本中时，用更短的“关系名 + 来源引用”替代重复事实。保留节点方向、关系名和来源位置；改写事实继续保留原文本。比较实际文本长度，选择更短表示。
2. **分离事实窗口与依赖窗口。** `window_scope='fact'` 仅围绕命中事实扩窗；原 `bundle` 配置围绕事实与依赖一起扩窗。两组共享同一批已绑定依赖。
3. **筛选自动依赖。** `dependency_mode='lexical'` 复用现有停用词过滤，自动依赖轮次与问题或事实正文至少重合一个有效词时保留；去掉消息角色前缀后计算。沿用无偏移显式绑定的识别方式，保留外部明确绑定的记忆束。`all` 保留现有依赖，`none` 构成纯事实窗口对照。
4. **重新检查双锚点成本。** 在去重后的表示上重新运行条件 Top-2，与 Top-1 共同计算 Pareto 前沿。

对之前分析作两处数据修正：

- 仅保留 Top-1 与 ±1 轮，实际召回为 **589/896，65.74%**。原 w=1 保留 873 条，两者差 **284 条 = 159 条窗口外依赖支持 + 125 条依靠依赖周边窗口覆盖的支持**。
- “159 条”定义为旧依赖阶段新增、且落在事实 ±1 轮之外的官方支持轮次。这一划分衡量证据位置；关系类型可通过后续语义依赖标注进一步确认。

检索与写入保持相同输入：每个命中 Session 使用最大词面相关轮次形成基础关系，经 `HReConGraphMemory` 写入后生成自然四维 `source_spans`。单锚点的 11 组配置共享同一上下文对象。问题与来源决定选择；`answer`、`has_answer` 和机制样本必要证据用于装配后的评分。

## 代码变更

### `h_recongraph/memory/relinking.py`

`render_text()` 增加 `deduplicate_edge_facts=True`，在来源已选定后复用其正文：

```python
covered_source = next(
    (episode_id for episode_id, text in sources if fact in text), None
)
edge_text = fact
if deduplicate_edge_facts and covered_source is not None:
    relation = getattr(edge, 'name', None) or 'RELATION'
    reference = f'{relation} [source={covered_source}]'
    if len(reference) < len(fact):
        edge_text = reference
blocks.append(f'[EDGE] {source} -> {target}: {edge_text}')
```

写入对象的 `edge.fact` 完整保留。渲染时，重复长文本变为来源引用；同一引用继续使用现有输出去重。特别是在本次 `RELEVANT_TURN` 适配中，同一 Session 的两个锚点拥有相同节点端点，引用化后可共享一行关系，第二锚点成本随之接近实际新增正文成本。

`source_indices()` 与 `_source_bundle()` 接入 `dependency_mode`、`window_scope`：

```python
anchor_tokens = ranker.tokenize(self.query)
for index in fact_indexes:
    anchor_tokens.update(unit_tokens[index])
dependency_indexes = {
    index for index in dependency_indexes
    if unit_tokens[index] & anchor_tokens
    or any(span.text in paragraphs[index] for span in explicit_spans)
}
base_indexes = fact_indexes | dependency_indexes
window_anchors = fact_indexes if window_scope == 'fact' else base_indexes
```

后续继续执行所属来源内的索引扩展、并集和原序输出，保留消息内部换行、重复原始轮次及同源副本去重。

### 去重后的双锚点与 Pareto

| 去重配置 | Top-1 平均 Token / 支持轮次 | 条件 Top-2 平均 Token / 支持轮次 |
| --- | ---: | ---: |

相同 w=1 下，第二锚点的平均成本从先前的 **+569.19 Token** 变为 **+11.89 Token**，新增四条支持轮次。三组条件 Top-2 均进入新的共同 Pareto 前沿。因此，先前的前沿结论依赖重复渲染条件，修复后按新成本重新判断。

在汇总计数 micro 下，条件 Top-2 w=1 以较低成本达到 Top-1 w=2 的同等 877 条召回；macro 下两者因支持证据的逐题分布差异同时处于前沿。达到整体或条件召回 90%/95% 参考线的最低成本配置仍是 **Top-1、去重 w=1**。本批默认继续保持 Top-1；条件 Top-2 保留为消融选项。

### 机制样本与写入诊断

自然绑定的 16 个机制样本，在“词面依赖 + 事实窗口 w=1”下保留 **35/35** 片段、完整 **16/16**、探针 **16/16**，平均 **53.44 Token**，较全文的 76.69 减少 **30.32%**。显式完整绑定在“词面依赖 w=0”下继续保持 **35/35**、完整与探针 **16/16**，平均 **56.50 Token**，较全文减少 **35.47%**。

另对现有写入构造器的触发规则进行来源文本诊断：限定维度按子串触发的段落为 **16,284** 个，按英文词边界匹配时为 **8,573** 个；其中 **7,711** 个仅有子串触发。这 7,711 个段落构成待校准的规则差异集合，语义有效性需要结合事实与来源抽样核验。明确的子串匹配例包括 `specific` 中的 `if`、`viable` 中的 `via`。计数单位为原始段落，长消息内部的多个段落分别统计。

本批得到的优先方向是：**先校准写入触发规则与事实—依赖作用域，再评价窗口策略。** 整轮助手回复用作事实锚点时，词汇集合较大，单词交集容易覆盖多数候选；该适配方式也需要与命题级事实表示配对研究。以去重全文为统一参照，本次成本至少减半的配置为纯事实窗口，其召回为 65.74%；高召回配置的成本缩减仍较小，下一步以写入绑定精度作为主要研究变量。
