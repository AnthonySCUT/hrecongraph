# 09：连续更新与增量记忆束

日期：2026-10-20。工作副本：`26-10-16-逐代码审核`。承接第八批完整记忆束的局部增改替删，在后续轮次仅提交新证据的条件下，完成连续更新与读取配对。

## 核心改动

**后续对话只提交变化维度，控制器从旧记忆束继承其余证据。** 当前束沿既有 M1/M2 关联同步更新，再进入图来源写入和检索恢复。

```text
新一轮：操作 + 新 source_spans
              ↓
append_spans：追加证据 / span_updates：替换指定维度
              ↓
旧束未变维度 + 本轮变化 → 当前有效证据束
              ↓
重建 cause / condition / validity → 同步 M1/M2 → 更新图来源
              ↓
缓存读取 / 新 controller 来源恢复读取
              ↓
changed / kept / 四维证据完整保留 / stale misuse
```

| 操作 | 第八批行为 → 第九批行为 |
|---|---|
| 补充限定、原因或路径 | 提交完整替换束 → 用 `append_spans` 追加新证据，已有维度保留 |
| 修改一个维度 | 提交完整替换束 → 用 `span_updates` 替换指定维度，其余维度从旧束继承 |
| 同维度多条证据 | 调用方重组全束 → 支持追加，重复证据按来源、维度、文本与位置去重 |
| 撤去某一维度 | 提交完整替换束 → 以空列表显式清除，例如 `{'causal': []}` |
| 替代、删除 | 沿用 `supersede / delete`，纳入连续回放和来源恢复验证 |

### 接口与更新单位

`append_spans` 表示“原约束继续有效，再增加这一条”；`span_updates` 表示“该维度以本轮列表为准”。指定维度内的多条证据作为一个列表替换，调用方只提交该维度。

```python
# 第 1 轮：既有束包含事实、限定、路径、因果。
memory = await controller.add_memory(initial_bundle)

# 第 2 轮：追加条件，保留之前的时间限定与其余三个维度。
memory = await controller.update_memory(
    memory.memory_id,
    operation='modify',
    append_spans=[
        SourceSpan(
            evidence_id='turn-2',
            field='constraint',
            text='仅工作日生效。',
            start=0,
            end=7,
        )
    ],
)

# 第 3 轮：只修改原因，事实、限定、路径从当前束继承。
memory = await controller.update_memory(
    memory.memory_id,
    operation='modify',
    span_updates={
        'causal': [
            SourceSpan(
                evidence_id='turn-3',
                field='causal',
                text='原因是兼容旧系统。',
            )
        ]
    },
)

# 后续：替代为新束，再删除当前束。
memory = await controller.update_memory(
    memory.memory_id, operation='supersede', replacement=new_bundle
)
await controller.update_memory(memory.memory_id, operation='delete')
```

证据的 `evidence_id / start / end` 始终指向各自原始轮次。当前 `raw_content` 按有效证据重组为段落，旧原因或旧限定随维度替换退出当前束。

### memory_unit.py：从整束替换到维度合并

改前：记忆对象保存完整正文和证据，由调用方准备替换束。

改后：以下方法从旧束继承未指定维度，将指定维度替换为新列表，再追加本轮新证据。

```python
    def with_span_updates(
        self,
        span_updates: dict[MemoryDimension, list[SourceSpan]] | None = None,
        append_spans: list[SourceSpan] | None = None,
    ) -> 'UnifiedMemoryUnit':
        """Merge changed dimensions into the current bundle, retaining other evidence."""
        updates = span_updates or {}
        spans = [
            span.model_copy(update={'field': dimension}, deep=True)
            for dimension in ('fact', 'constraint', 'path', 'causal')
            for span in updates.get(
                dimension, [span for span in self.source_spans if span.field == dimension]
            )
        ]
        spans.extend(span.model_copy(deep=True) for span in append_spans or [])
        spans = list(
            {
                (span.evidence_id, span.field, span.text, span.start, span.end): span
                for span in spans
            }.values()
        )
        revised = self.model_copy(deep=True)
        revised.raw_content = '\n\n'.join(dict.fromkeys(span.text for span in spans))
        revised.source_spans = spans
        revised.evidence_ids = list(dict.fromkeys(span.evidence_id for span in spans))
        revised.created_at = utc_now()
        return revised
```

合并顺序为 fact → constraint → path → causal，再追加新证据。深复制保留旧对象，生成的当前束交给已有版本与层级更新流程处理。

    async def add_memory(self, memory: UnifiedMemoryUnit) -> UnifiedMemoryUnit:
        """Write one M1/M2 bundle with its fact, constraint, path and causal evidence."""
        memory.evidence_ids = list(
            dict.fromkeys(
                [*memory.evidence_ids, *(span.evidence_id for span in memory.source_spans)]
            )
        )
        state = self.semantic_state_constructor.construct(memory)
        memory.semantic_state_id = state.state_id
        memory.semantic_state = state.model_dump(mode='json')
        if not any(
            span.field in {'fact', 'constraint', 'path', 'causal'} for span in memory.source_spans

            ]

### semantic_state.py：限定和原因随证据刷新

改前：规则从正文识别 cause / condition，validity 选择单个时间或条件片段。

改后：传入的 constraint / causal 证据直接定义当前 condition / cause；多条限定合成当前 condition，validity 绑定同一组限定证据。

```python
# Explicit dimension evidence defines the current condition and cause.
for dimension, field in (('constraint', 'condition'), ('causal', 'cause')):
    bound = [span for span in memory.source_spans if span.field == dimension]
    if bound:
        spans = [span for span in spans if span.field != field]
        spans.extend(span.model_copy(update={'field': field}) for span in bound)
        value = '; '.join(dict.fromkeys(span.text for span in bound))
        if field == 'condition':
            condition = value
        else:
            cause = value

validity = (
    condition
    if any(span.field == 'constraint' for span in memory.source_spans)
    else temporal_scope or condition
)
if validity is not None:
    validity_sources = (
        [span for span in spans if span.field == 'condition']
        if validity == condition
        else [span for span in spans if span.text == validity]
    )
    spans.extend(span.model_copy(update={'field': 'validity'}) for span in validity_sources)
```

例如“仅十月生效”追加“仅工作日生效”后，condition 与 validity 同时保留两条限定；随后替换 constraint，状态按新限定刷新。因果维度同样按当前 causal 证据生成 cause。

### 实验：同一段连续对话的配对回放

数据由 8 组显式标注的机制样本组成：Atlas 缓存、Beacon 审核、Cedar 预约、Delta 配送、Orion 与 Vega 两组中文流程、博物馆路由、实验室管线。每组另有两条独立旧记忆用于 kept 检查。

每组固定 11 步：

| 轮次 | 操作 | 本轮输入 |
|---|---|---|
| 1 | add，并经现有巩固入口建立 M2 | 初始 fact |
| 2 | append | constraint |
| 3 | append | causal |
| 4 | append | 两段 path |
| 5 | append | 第二条 constraint |
| 6 | modify | 替换 constraint 列表 |
| 7 | modify | 替换 causal |
| 8 | modify | 替换 path |
| 9 | modify | 替换 fact |
| 10 | supersede | 新事实及其完整四维证据 |
| 11 | delete | 当前束 ID |

两条件共享各轮 `input`；`expected` 仅交给评分器：

- **仅新片段整束替换（replace_fragment）**：把本轮片段作为 replacement，直接执行现有整束替换入口。
- **增量合并（incremental_merge）**：追加轮次使用 append_spans，局部修改使用 span_updates。

配对重点是“后续只传变化片段”时历史合并机制的作用。第八批使用完整替换束的用法继续由原有测试回归。

每次写入之后，分别执行：
`warm/full_source`、`warm/evidence_bundle`、`restored/full_source`、`restored/evidence_bundle`。
warm 使用当前控制器；restored 新建控制器，从已命中的图来源 envelope 恢复状态。图接口通过 `ReplayGraphiti` 内存驱动运行，实际调用现有 controller 与 store 的写入、移除、检索和恢复代码。

8 组 × 11 步 = **88 次对话操作**；两条件与四个读取视图共产生 **704 条检查记录**。JSON 保存各条记录的实际 spans、逐轮目标、返回文本、kept 检查和 stale 命中。

### 指标口径

| 指标 | 判定与分母 |
|---|---|
| changed | 当前活动 ID 正确；本轮改变维度的证据集合与目标一致；新证据进入读取文本。每视图 88 次操作 |
| kept | 两条独立旧记忆的正文、证据、语义状态、图绑定、版本及图来源保持原值。每视图 88 × 2 = 176 次检查 |
| 四维证据完整保留 | 对每个有目标证据的维度，全部证据及其原始位置在各活动层级保留，并出现在读取文本。每视图 272 个维度检查 |
| stale misuse | 已撤去的旧证据文本出现在当前读取上下文的轮次占比；每视图 48 个含历史替换或删除的检查点 |

四维分母为 fact 80、constraint 72、path 56、causal 64。各轮只考核当时已出现的维度；删除轮通过 changed 与 stale 检查。stale 指标在本批统计**读取上下文中的旧证据暴露**。
