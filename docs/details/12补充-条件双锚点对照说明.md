# 第十二批补充：条件双锚点的召回与成本对照

## 核心改动

保留每个命中 Session 的 Top-1 默认行为，增加条件 Top-2 配置：次高轮次达到最高词面得分的 50%，且与问题至少重合两个不同的有效词时，才纳入第二锚点。复用现有停用词过滤；并列按原始轮次先后选择，输出按原文顺序排列。

这是一项锚点策略消融。两组共享相同问题、命中 Session、自然写入状态与依赖绑定；每组内部固定锚点，再比较全文与 w=0/1/2。问题和原文决定锚点，官方 `answer`、`has_answer` 用于装配完成后的评分。

对所提五项意见的核对：

| 意见 | 核对结果与研究含义 |
| --- | --- |
| 收紧依赖可能损失原先新增的 266 条真证据 | 其中 107 条位于 Top-1 的 ±1 轮内，159 条在该窗口之外。收紧绑定时应逐条记录这些证据的去留；88%～92% 属于待测预测。 |

## 代码变更

`h_recongraph/examples/evaluate_longmemeval_read.py` 新增 `fact_turn_indexes()`，并将 `max_fact_anchors=1` 贯穿上下文构建、评测和命令行。

```python
query_tokens = ranker.tokenize(query)
overlaps = [len(ranker.tokenize(turn_text(turn)) & query_tokens) for turn in session]
ranked = sorted(range(len(session)), key=lambda index: -overlaps[index])
selected = ranked[:1]
if max_anchors == 2 and len(ranked) > 1:
    first, second = ranked[:2]
    content_overlap = len(ranker.tokenize(session[second]['content']) & query_tokens)
    if content_overlap >= 2 and overlaps[second] >= 0.5 * overlaps[first]:
        selected.append(second)
return sorted(selected)
```

对固定 query，原词面得分等于重合词数除以 query 有效词数，因此上面的计数比较与相对得分比较一致。两个有效词的下限按消息正文计算，角色标签单独排除；重复出现同一个词计为一个重合词。

每个选中轮次形成一条现有 `RELEVANT_TURN` 适配关系；`source_fact_indices` 保存所选位置。固定检索记录改为按 episode 收集多条关系，保存 `graph_facts`，沿用原 `graph_fact` 字段。`anchor_policy` 记录阈值。原 `relinking.py` 窗口与依赖装配保持现有行为。

`tests/test_h_recongraph_longmemeval.py` 增加三个核心测试：阈值及不同实词数；并列选择与原序；双关系来源关联及去除答案标注后仍保持相同锚点。

## 验证结果

同一 LongMemEval oracle 500 题，931 个命中 Session，896 条官方支持轮次，其中命中来源包含 880 条。第二锚点在 **682/931（73.25%）** 个 Session 激活，锚点总数从 931 增至 1,613。

两组数据 SHA-256 一致：`821a2034d219ab45846873dd14c14f12cfe7776e73527a483f9dac095d38620c`。逐题核对命中 Session 与语义绑定摘要一致；Top-1 的 2,000 条配置记录在 Token、支持轮次及实际输出索引上复现第十二批结果。估算 Token 统一使用现有 `len(text)//4`；渲染预热后计时三次。

| 配置 | Top-1 支持轮次 | 条件 Top-2 支持轮次 | Top-1 平均 Token | 条件 Top-2 平均 Token | 每题 Token 增量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| full_source | 880/896 | 880/896 | 7,246.39 | 7,803.74 | +557.35 |
| w=0 | 676/896 | 730/896 | 6,727.29 | 7,316.36 | +589.06 |
| w=1 | 873/896 | 877/896 | 7,149.28 | 7,718.47 | +569.19 |
| w=2 | 877/896 | 880/896 | 7,236.29 | 7,794.82 | +558.52 |

条件 Top-2 的 w=1 整体召回为 **97.88%**，裁剪条件召回为 **99.66%**；相对 Top-1 增加四条支持轮次，分别来自 multi-session、single-session-assistant、single-session-preference、temporal-reasoning，各一条。完整保留题数从 462/479 增至 466/479。w=0 新增 54 条，w=2 新增三条。配对结果中，原已保留支持证据全部继续保留。

成本拆分揭示主要来源：当前实验适配器将选中轮次的完整文本用作 `edge.fact`，渲染时同时输出 `[EDGE]`。条件双锚点的 w=1 每题新增约 **557.36 Token 的非来源输出**，新增来源正文约 **11.83 Token**。完整轮次关系文本贡献了主要增量，窗口选入更多来源正文的增量较小。该成本来自当前整轮图关系适配方式。

统一以 Top-1 全文的 7,246.39 Token 为参考，条件双锚点 w=1 平均成本高出 **6.51%**。两组共同计算整体/条件召回的 micro/macro Pareto 前沿，前沿均由原 Top-1 四组配置组成：Top-1 w=1 以更低成本超过双锚点 w=0 的召回；Top-1 w=2 以更低成本达到双锚点 w=1 的 micro 召回；Top-1 全文以更低成本达到双锚点 w=2 的召回。

结论：**默认保持 Top-1，条件 Top-2 作为可复现消融配置保留。下一阶段优先改善事实—依赖作用域绑定，并评估图事实文本与来源正文的重复输出成本。** 本次结果衡量官方支持轮次保留与实际渲染上下文成本，模型问答评价可在冻结配置后开展。
